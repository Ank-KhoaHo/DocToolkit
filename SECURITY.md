# Security policy

## Reporting a vulnerability

**Report privately, through GitHub:** open
<https://github.com/Ank-KhoaHo/DocToolkit/security/advisories/new>, or use *Security → Report a
vulnerability* on the repository. That channel is private between you and the maintainer until an
advisory is published.

**Please don't open a public issue for a suspected vulnerability.** Both packages are on
nuget.org, so a public report is a disclosure to every consumer at once, before there is anything
for them to upgrade to.

There is no security email address, deliberately — an unmonitored inbox is worse than no inbox.

### What helps

The version you're on, the shortest input that reproduces it, and what you expected instead. If it
concerns HTML conversion, the markup matters more than the surrounding code — this library's
attack surface is almost entirely "what does a hostile document make it do".

### What to expect

This is a small project with a single maintainer, so: acknowledgement as soon as it is seen, and a
fix in the next release once confirmed. **No guaranteed response time is offered**, because one
that cannot be met reliably is worth less than an honest statement that there isn't one.

## Supported versions

| Version | Supported |
|---|---|
| Latest `0.x` release | Yes |
| Anything older | No |

The package [stays below `1.0.0` permanently](CONTRIBUTING.md#marking-a-breaking-change) and there are no maintenance branches, so
fixes ship in the next release rather than being backported. Upgrading to the newest `0.x` is the
only supported remediation path. A published nuget.org version can be unlisted but never deleted or
replaced, so a vulnerable version will remain resolvable to anyone who pins it explicitly.

## Scope

### In scope

- **Any bypass of the remote-image guard** — reaching a loopback, private or link-local address
  while `RemoteImageOptions.AllowPrivateAddresses` is `false`; reading a local file through
  conversion; the byte cap or timeout not being enforced; a redirect being followed.
- **A crafted document causing resource use well beyond the documented limits** — memory, time, or
  disk disproportionate to its size.
- **Anything in the resolved dependency closure that reaches consumers.**
  [`THIRD-PARTY-NOTICES.txt`](src/DocToolkit/THIRD-PARTY-NOTICES.txt) lists it with versions.
- **A defect in the offline guarantee** — any default code path opening a network connection. The
  test suite asserts zero connections across the whole public API; a case it misses is a real
  finding.

### Known limits, already documented

These are stated in the package README and are not vulnerabilities in themselves. A report showing
one is *worse than documented* very much is.

- **The remote-image guard is not a complete SSRF defence.** A host's address is resolved and
  checked, then resolved again by the HTTP stack when it connects. A DNS answer that changes
  between those two moments defeats the check. Closing that properly means connecting to the
  validated address directly while carrying the original hostname in SNI and the `Host` header,
  which breaks virtual hosting and certificate validation — it needs its own design, and is not an
  oversight.
- **`RemoteImageOptions` bounds each fetch, not the whole document.** A document naming many remote
  images has no aggregate ceiling of its own; bound it with a `CancellationToken`.
- **`AllowPrivateAddresses = true` reaches private addresses.** That is what it is for.
- **Enabling remote images makes outbound requests at all.** The opt-in is explicit and off by
  default.
- **Not every IPv6 transition mechanism is unwrapped.** IPv4-mapped, NAT64 (RFC 6052 and RFC 8215),
  6to4, Teredo, IPv4-translated and IPv4-compatible are. ISATAP and 6rd are not. A working bypass
  through one of those is worth reporting even though it is listed here.

### Out of scope

- Vulnerabilities in Word, Excel, PowerPoint or a PDF reader, reached via a file this library
  produced. Report those to the vendor.
- Anything requiring the attacker to already control the machine running the conversion, or the
  configuration passed to it.
- Reports generated by a scanner with no demonstrated impact on this library.

## A note on where the real boundary is

This library converts documents. If it converts **untrusted** documents, the guard described above
raises the cost of an attack but is not the only thing that should stand between hostile markup and
your internal network. Egress-filter the service at the network layer as well. That advice is in
the package README too, and it is meant.
